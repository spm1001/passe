The eval harness in tests/eval/ tests whether Claudes use passe correctly — it's not a unit test suite, it's a Claude behaviour test. The key finding from the first baseline: connection_error scenarios are the weak spot. Specifically, when a Claude is told "Mac is closed" and asked to screenshot a page, Sonnet just fires `passe look` without considering the connection context 80% of the time. The architecture is clean (Toise A across all 8 checks, only verbs.py at 1310 lines needs watching), so improvements should focus on the connection model — making errors Claude-actionable rather than raw "connection refused" — not on code restructuring. There's also a subtle finding about eval methodology: putting passe context in the API system param vs in the user message produces different Sonnet behaviour on the same scenarios, which suggests SKILL.md positioning matters as much as content.
