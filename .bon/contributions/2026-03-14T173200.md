The readability-lxml + markdownify middle tier was proposed as a layer between
trafilatura and Chrome, but bench data (31 fixtures, 7 categories) showed it
scores 0.648 overall vs trafilatura's 0.846. It doesn't outperform trafilatura
on any category. Don't re-propose this — the data is in tests/bench/. If a
specific page type emerges where readability wins, revisit then.

The quality gate thresholds (0.35 composite, 50 min words, 0.20 stop words ratio,
0.33 link density) were set by one round of tuning against the corpus. Two bugs
found and fixed: CAPTCHA false positives on Wikipedia (keyword in scripts, not
actual challenges) and stop words penalty triggering on large technical documents
with legitimate low stop-word ratios. The thresholds could be refined with a
systematic sweep using the bench harness.

When testing cmd_fetch, always mock `passe.fastpath.try_http_fetch` to return None
— otherwise the test makes real HTTP calls and the fast-path may short-circuit
before reaching the code you're actually testing.
