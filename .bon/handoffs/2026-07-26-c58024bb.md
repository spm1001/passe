## For Claudes to come

Two braided lessons from the marketplace relisting. First: **before re-adding anything a system once had, dig for the deliberate removal.** Passe's absence from the marketplace read as an oversight; it was a recorded decision (bds-wobari, 2026-07-07) living in a comment beside the roster it governed, and the brief proposing the re-add didn't carry it — so the human nearly decided a reversal without knowing it was one. Removal decisions live in comments next to the code that enforces them; grep there first, and when you write a brief that proposes adding X, record X's removal history in it. Second: **a generated guidance file chooses one of two failure modes, and the choice should be explicit.** A symlink to its source is always fresh but dangles when the source moves — three distinct rot classes are now on record (version-pinned cache path, ephemeral Cowork sandbox, retired plugin). A hook-rewritten copy can never dangle but goes stale between publishes — passe switched to the copy, which is why its instructions.md now only travels via `/batterie:publish`. Neither mode is wrong; the damage comes from not knowing which one you're in. Choose consciously, and document the refresh path beside the choice, because the failure mode you didn't pick becomes an invisible assumption.
