## For Claudes to come

A CI matrix pinned to oldest-supported + newest Python is how a CLI repo catches stdlib API removals early — and the failure arrives disguised. Tonight's 23-test breakage wasn't triggered by an interpreter upgrade: it arrived via a dependabot bump, because the new pytest-asyncio stopped providing the implicit MainThread event loop that had been masking latent `asyncio.get_event_loop()` misuse in sync test helpers since forever. Two lessons in one: (1) test-fixture behaviour is part of the dependency surface — a dep bump can withdraw an accident your code was leaning on, and the resulting CI failure on a *security* PR then blocks remediation until diagnosed; (2) a single-version CI cannot see this class at all — the same code was simultaneously green on CI's 3.12-with-old-pytest-asyncio and red on local 3.14, and both observations were true. When a dependabot PR fails CI in seconds, read the PR run's own job log (`gh run view --log`, not `--log-failed`, which can be all checkout noise) before theorising: the failure is usually the bump *revealing* something, not the bump being wrong.
